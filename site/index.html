Native UI Guides Accessibility Contributing

HTML-first · zero runtime dependencies

Write HTML. Get an interface people want to use.

Native UI adds visual hierarchy, resilient layout, and restrained polish to the semantics the browser already understands.

Start with one stylesheetRead the thesis

1. Import CSS

npm install @ifaka/native-ui
<link rel="stylesheet" href="native-ui.css">

No component runtime, provider, or generated DOM.

2. Write HTML

<form>
  <label>Email <input type="email" required></label>
  <button type="submit">Save</button>
</form>

Labels, validation, focus, and submission stay native.

3. Add layout intent

<section class="nui-grid">...</section>

Classes describe composition, not every visual property.

See the browser do the work

Native disclosure

This content is available without JavaScript, preserves source order, and uses the browser’s keyboard behavior.

JavaScript disabled? Content, links, forms, validation, focus, and native actions still work. Optional behavior is never the only path.

Small vocabulary, explicit contracts

Public layout: nui-container, nui-readable, nui-stack, nui-cluster, nui-grid. Compositions: card, badge, alert, toolbar, empty-state, field-actions, table-overflow, dialog-sections, popover-surface, responsive-navigation. Variants use data-variant="primary|danger|quiet".

Every name above is synchronized with the manifest and exercised by the documentation test.
